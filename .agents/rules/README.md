# Границы изменений и эскалация

Используйте эти правила перед изменением файлов и когда проверка после правок выявила проблему, а её устранение может изменить поведение продукта или выйти за согласованный объём.

- При реализации функциональности, добавлении или изменении логирования, а также написании или изменении тестов обязательно применяйте [правила безопасности данных](security.md).
- При реализации функциональности, исправлении дефектов, рефакторинге, code review, а также написании или изменении тестов обязательно применяйте [правила разработки](coding.md).
- При продуктовых изменениях, исправлении дефектов, рефакторинге и изменении тестов применяйте [правила тестирования](testing.md): зафиксируйте baseline до правок, выполните TDD-цикл и повторите baseline после завершения.
- Перед любыми изменениями файлов следуйте [правилу планирования изменений](change-planning.md).
- Не расширяйте объём исправления без явного согласования.
